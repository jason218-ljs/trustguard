哪个数字是编的

把「一段结论」和「它引用的原始材料」一起喂进去，TrustGuard 逐条指出哪个数字在材料里找不到出处、哪句话和来源矛盾、哪个变化率算错了——每条都带证据原文，可以直接拿去核对。纯规则模式零依赖、零 API key、离线可跑。

$ pip install trustguard-ai
$ tguard demo

看一个真实例子

左边是一段看起来很专业的 AI 结论，右边是它的问题

这是一份量化策略报告里的一段话。数字齐全、逻辑通顺、措辞专业——它完全可能被直接贴进给客户的邮件里。

输入

本季度组合取得显著超额收益：AlphaForge 系统选出的标的组合年化收益 32.4%，显著高于基准 8.1%，说明该因子体系在 A 股市场长期有效，预计明年收益可达 40% 以上。
来源 [backtest-report]：回测显示，组合年化收益 32.4%，同期基准年化收益 8.1%，超额收益 24.3 个百分点。
来源 [methodology]：因子有效性检验采用 IC 与分层回测，样本区间 2018–2025。

输出

⚠ WARN mode=rule · 1 个问题 · 3 条标注
数字 40% 在来源材料中找不到出处
证据：有效，预计明年收益可达 40% 以上。
ℹ️ 标注：此处可能存在外推假设（以过去推未来）——「预计」
ℹ️ 标注：此处可能存在因果假设——「说明」
标注项不参与判定，仅供人工复核。

为什么 32.4% 通过了，40% 被拦下？

32.4% 和 8.1% 都能在来源里逐字找到。40% 不能——它是「预计」，但没有任何材料支持这个数字。

工具不判断「这个预测对不对」，那不是它能做的。它只回答一个可判定的事实：这个数字有没有依据。而这恰恰是人在复核时最容易跳过、后果最严重的一步。

实测

最值得看的不是最好的那行，是中间那行

30 条人工标注样本（20 条含缺陷 + 10 条干净），11 种缺陷类型。

中间那行是关键：把 LLM 朴素地接进每个检查器，召回从 75% 涨到 100%，但误报从 0% 涨到 60%，F1 只从 85.7% 挪到 87.0%——多花的 token 没有换来净收益，只是把「漏报」换成了「误报」。

逐条归因后发现，全部效果来自一个维度：未言明的假设。它对召回的贡献是 0（另外两个检查器已经抓到了所有语义缺陷），却贡献了全部误报。于是按实测证据把这一维度降级为「只提示、不判定」——这是被数据逼出来的设计，不是偏好。

设计主张

刚性任务交给代码，柔性任务交给模型，有些事根本不该自动判

数值比对、算术校验、方向矛盾、近似笔误——这些可以被精确判定，所以用纯规则：零误报、可解释、可复现、不需要 API key。

语义错位、隐藏假设、与来源的实质冲突——这些需要理解语义，所以交给模型，但由确定性层兜底校验它的输入。

至于「找出未言明的假设」——它没有天然的停止条件（任何结论都依赖无穷多隐含前提），模型的自我评定也未经校准。所以它只提示，不判罪。
